# Real-world KYC failure methods (2024 to 2026) and what TrueID Shield does about each

Researched October 2026. Vendor figures are directional (different methods and definitions); regulator and
law-enforcement sources are primary. "Covered" means implemented and tested in this repository, not certified.

## 1. The 2024-25 failure methods

| Method (source) | What went wrong in the real world | TrueID Shield defence | Status |
|---|---|---|---|
| **AI-altered identity documents**: FinCEN alert FIN-2024-Alert004, Nov 2024 | GenAI edits or fully generated ID images pass visual checks; FinCEN red flags include documents that disagree with each other | Issuer-signed QR (Ed25519, full 12-digit ID, all fields) compared with OCR and the form. A generated card has no valid signature (hard reject); an edited one contradicts its own QR (hard reject when the print is read confidently, review when unreadable). New: AI-generator markers in image metadata (IPTC `trainedAlgorithmicMedia`, generator names) block automatic approval | Covered |
| **Deepfake selfies / manipulated video**: FinCEN Nov 2024; FBI IC3 Dec 2024 | Face-swapped or synthesised faces presented as live; FinCEN red flags include third-party webcam plugins and photos matching galleries of AI faces | Server-issued head-turn challenge (random order, single use, bound to the applicant session, 3 min TTL). The server checks one face per frame, every frame matches the selfie, and the turn direction from facial landmarks. Client-side "passed" is ignored. New: a selfie seen before (perceptual hash) blocks approval | Covered (pre-recorded deepfakes); a real-time face swap that follows instructions is NOT stopped by this alone, see section 3 |
| **Camera / media injection**: Jumio, Aug 2025; iProov 2025 (virtual-camera attacks up 2,665% in 2024) | Virtual cameras and emulators feed synthetic video straight into the capture pipeline | Active camera label reported by the browser blocks approval when it is a known virtual camera. Labelled honestly as a **client-reported hint** (it can be renamed) | Partial: no device attestation in a web app |
| **Deceiving human video-ident operators**: Chaos Computer Club, Aug 2022 (six providers) | Paint and open-source video tools fooled both human agents and automated checks | No decision rests on a human looking at video. Evidence is machine-checked, and a human can only approve against the system with a written reason; approving an automated REJECT needs a **second analyst** | Covered |
| **Stolen / synthetic identities**: Federal Reserve synthetic identity work | Real ID numbers combined with invented details; thin files that mature into bust-outs | Registry lookups (identity, PAN linked to the full ID and the same person), SIM age, CKYC, bureau depth, face against the issuer photo, and the cross-application identity graph | Covered (mock registries) |
| **Insider assistance / skipped checks**: CBI, June-July 2025 (8.5 lakh mule accounts across about 700 branches, opened without proper KYC; bank officials among the accused) | Staff opened accounts without doing the checks | There is no code path that approves without every required check passing. Every decision is stored with its policy version and evidence statuses. The audit log is **hash-chained** (`GET /api/audit/verify` detects any edited or deleted entry). Overrides against the system need a reason, and approving a rejected case needs a second analyst | Covered (sessions, not named accounts) |
| **Real people recruited as money mules**: RBI | Genuine documents and real faces, so classic KYC passes | New **mule-herding** check: one device onboarding several unrelated people in 7 days (same-surname households excluded) holds the case for a person, pattern "Possible mule recruitment", action: verify in person, open with limits and transaction monitoring | Partial: onboarding can only see the recruiter pattern; most mule detection happens after opening (transactions) |

## 2. What changed in 2026

| Development (source) | Implication | What we did |

| Entrust 2026 Identity Fraud Report: injection attacks up 40% year on year, deepfake selfies up 58% in 2025, about 1 in 5 biometric fraud attempts involve deepfakes | Liveness that the client grades itself is not evidence | Liveness is verified on the server against a server-chosen sequence; the upload path is labelled "not provided" and can never auto-approve |

## 3. Open limits (stated, not hidden)
- A real-time face swap that follows the head-turn instructions can pass a web liveness check. Production answer: certified PAD and injection-attack detection (ISO/IEC 30107-3, CEN/TS 18099) or device attestation in a native app, plus DigiLocker / Aadhaar offline e-KYC signed data instead of photographed cards.
- Camera labels and device IDs come from the browser and can be spoofed.
- Analysts are told apart by sign-in session, not named accounts, so the four-eyes rule is a demo of the control, not a production identity system.
- The mule-herding check sees only onboarding; most mule activity is visible only in transactions after the account opens.
- All registries are mocks; all numbers come from a synthetic population.
